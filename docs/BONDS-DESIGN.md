# 羁绊 / 宿敌 / 军师复盘 —— 设计规格

三个「只有本作做得出来」的方向。共同前提:卡池是 **2,300 位真实历史人物**,
他们之间有**真实存在的关系** —— 这是编造世界观的 CCG 永远拿不到的素材,
也是目前唯一还没被开采的一层护城河。

三者的实现成本都低于一个新卡包(羁绊/宿敌是纯数据 + 一条计数规则,复盘是接线)。

---

## 一、羁绊(结义 / 君臣 / 师徒)

**玩法**:场上同时存在特定几位名将时,全体获得增益。构筑因此有了**历史叙事** ——
玩家不是在配曲线,是在**重组一段历史**。

### 数据结构(新文件 `src/content/bonds.ts`)

```ts
export interface BondDef {
  id: string
  name: LocalizedText          // 桃園結義
  members: string[]            // ['liu-bei', 'guan-yu', 'zhang-fei'] —— 卡 id
  requires?: number            // 触发所需人数,缺省 = members.length(允许「三人到齐其二」这类)
  effect: { attack: number; health: number } | { costDelta: number }
  text: LocalizedText
  lore: LocalizedText          // 一句史料,点开能看 —— 与列传图鉴同源
}
```

首批候选(全部有立绘、有列传,可直接落):
| 羁绊 | 成员 | 效果 |
|---|---|---|
| 桃園結義 | 劉備 · 關羽 · 張飛 | 三人全体 +2/+2 |
| 臥龍鳳雛 | 諸葛亮 · 龐統 | 我方锦囊费用 -1 |
| 君臣相得 | 劉備 · 諸葛亮 | 诸葛亮费用 -2 |
| 江東二喬 | 孫策 · 周瑜 | 二人 +1/+2 |
| 鬼谷門下 | 孫臏 · 龐涓 | 二人 +2/+0(同门相残,只加攻) |
| 蕭何月下 | 劉邦 · 韓信 | 韩信费用 -3 |
| 漢初三傑 | 張良 · 蕭何 · 韓信 | 三人全体 +1/+1,抽一张 |

### 引擎实现:走**光环**,不要新 opcode

关键判断:羁绊 = 「场上有 X 和 Y 时给增益」,这**正是光环的语义**
(`aura` 已存在,且附魔层的撤销路径现成)。所以:

1. `resolve.ts` 的 `refreshInstance` / 光环重算处,增加一遍 bond 扫描:
   对每条 BondDef,若我方场上 `members` 齐了 `requires` 人,就给在场成员挂一条
   **光环来源的附魔**(与现有 aura 同一套 `removeEnchants(clampAlive: true)` 撤销)。
2. **不新增事件**:复用 `GeneralBuffed`(光环增益本来就走它)。UI 三处零改动。
3. 铁律 2 的红线照旧:**只能记附魔再 refresh,不能直接改数值**。

⚠️ 两个坑(实现时必查):
- 羁绊消失(成员被杀/被策反)时增益必须能撤销 —— 走光环路径就自动满足;
  **别用一次性 buffStats**,那没有撤销路径。
- 「光环消失可以杀人」是既定规则(炉石口径),羁绊断裂导致成员死亡是**正确**行为。

### 闸门
- `bonds.test.ts`:成员 id 真实存在、羁绊 id 唯一、成员不重复、效果非零;
- 组一副含完整羁绊的牌跑 `sim-balance` —— 羁绊是**同名卡共存**的强激励,
  要确认它没有把某个主义顶出 40–60% 带。

## 二、宿敌

羁绊的反面,戏剧性更强:**双方**在场时**都**拿加成 —— 历史上真打过的人在牌桌上重逢。

```ts
export interface RivalDef {
  id: string
  a: string; b: string          // 两张卡 id,分属敌我时触发
  effect: { attack: number; health: number }
  text: LocalizedText
  lore: LocalizedText           // 「长平之战,白起坑赵卒四十万」
}
```

首批:諸葛亮↔司馬懿 · 廉頗↔白起 · 項羽↔韓信 · 岳飛↔完顏宗弼(注:兀术无立绘,
需换人或只作文案)· 孫臏↔龐涓。

实现同样走光环,只是扫描条件从「我方场上」变成「我方有 a 且敌方有 b(或反之)」。

**为什么值得做**:它让玩家**去查史料**。「为什么我这张对他有加成?」→ 点进列传。
这是把游戏机制变成教育钩子的最短路径。

## 三、军师复盘

`src/ai/lethalSolver.ts` 的 `solveLethal` 现在只用来验证谜题与出提示。
把它接到**战报回放**上,一局打完逐帧扫描:

> 「第 7 回合这里有一条你没看见的斩杀线 —— 展开看」

### 接线点
- `replayStore` 已经存了每一帧的 `GameState`;
- 对每个「我方回合开始」帧跑一次 `solveLethal`(有节点预算,单帧很快);
- 命中则在 `ReplayScreen` 时间轴上打一个标记,点开走现成的 `describeSolution`。

### 注意
- **别用 greedy 的 `findLethal` 当扫描器**(见 [engine-vocabulary-and-modes]):
  它只搜直接打脸,遇守护即弃、不碰主公技/法术;必须用 `solveLethal`。
- 整局扫描要放 **Web Worker 或分帧**,别在主线程一次跑几十帧把 UI 卡住。
- 只标「你当时真能赢却没赢」的帧,别标那些赢面很小的 —— 噪声会让功能失去可信度。

**性价比**:别家做这个要专门训模型,本作只要接根线 —— 求解器早就写好了。

---

## 建议的落地顺序

1. **羁绊**(纯数据 + 光环扫描,零新事件,收益最大)
2. **宿敌**(同一套扫描,换个条件,几乎白捡)
3. **军师复盘**(接线为主,但要处理性能)

三者都不需要动服务器、不需要改协议、不需要迁移存档。
